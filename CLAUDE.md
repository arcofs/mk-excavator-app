# MK Excavator: notes for Claude

- Goal: drive both Mould King 4.0 modules of the 13112 excavator at the same time from one screen. Plan and phases: `docs/ROADMAP.md`.
- **Written from scratch.** Don't copy code from other Mould King projects (MoldQueen, mkconnect-python, BrickController2 and so on). Protocol knowledge comes from our own recordings of the stock app, written up in `docs/protocol.md` and proven by unit tests against those recordings.
- `:protocol` is pure Kotlin with no Android imports. `:app` holds the UI, the Bluetooth broadcaster and settings.
- Never weaken the safety rules in `docs/ROADMAP.md`.
- Workflow: solo project. Work directly on `main`, no branches or pull requests. Commit and push once a feature is ready and builds, tests and lints clean locally; batching several features into one push is fine. CI runs on every push to `main`.
- Code style: Kotlin official style, 2-space indent (as generated by the template).

## Commands (Windows)

`JAVA_HOME` points at Android Studio's bundled JDK; Gradle provisions JDK 17 for compiling.

```powershell
.\gradlew.bat assembleDebug                              # build
.\gradlew.bat installDebug                               # install on the Pixel over USB
.\gradlew.bat testDebugUnitTest :protocol:test lintDebug # same checks as CI
```

Test phone: Pixel 8 Pro, Android 17, connected over USB.

To see what any app broadcasts to the boxes, listen from the PC (Windows Bluetooth, needs `bleak`):

```powershell
python -m venv .venv; .\.venv\Scripts\pip install -r tools\requirements.txt
.\.venv\Scripts\python tools\ble_sniff.py --seconds 300 --log sniff.log
```
